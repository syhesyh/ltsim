3. 例子二（大 GEMM）：double weight bank 的装载-计算重叠

M=1024, K=1280, N=1920（INT8）。决策：tile_m=128, tile_k=tile_n=320 → 8 m块 × 4 k块 × 6 n块；绑 {w0,w1} n_split；banks: alternate。机器参数：装一块权重 20 拍（320行/每拍16行），一个 (m,n,k) 的 acc 占 128 拍，block_switch_gap=5，lw_to_acc_gap=1。

double buffer 由三条边编出来（无需新机制）：

4. 与 GTSim 的本质区别

GTSim（GPU）LTSim（LPU）
调度模型周期驱动：每拍所有模块 step 一遍，scheduler 逐拍决定发哪条指令解析式：B2 等式定链内偏移，B3 一次性定每条链的起始时刻
调度器代表硬件动态 warp 调度理想静态编译器
流水重叠逐拍仿真的涌现结果偏移等式 + 日历区间重叠的解析结果
double bufferbuilder 手工连依赖（k 轮 load 依赖 k−2 轮 compute）决策 banks: alternate + 三种 order 边，日历验证重叠
资源竞争发射时查端口/队列，stall 事后统计earliest_fit 放置时一次跳跃，bound_by 直接记录被谁卡住
输入C++ 硬编码 builder，无文件格式tile_graph.json（不含周期数），通用 DAG builder 生成

5. 总结：一个算子的执行时刻由什么决定

① 链内偏移 o（B2）由延迟 L 和传播 hop 的等式决定：ASAP 正向 → ALAP 反推对齐 → 核对。流不能等待，所以相对时刻刚性。
② 依赖 est + 优先级（B3）链间边给出 est；bottom-level 优先级让关键路径上的链先挑资源。
③ 资源日历 earliest_fit（B3）est 处放不下就跳到冲突结束的最早时刻；bound_by 记录被哪条边/哪个资源卡住。

最终：start(算子) = T链 + o节点 —— 结果总是"估计值 + 下界 + 关键路径"，偏乐观，代表好编译下能达到的性能。
